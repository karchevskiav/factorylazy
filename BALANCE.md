# Баланс и игровые механики — проектные заметки

> Документ-рассуждение. **Ничего пока не реализовано.** Цель — решить проблему «стены
> роста» и наметить новые механики, естественные для idle-игры. Числа ниже —
> иллюстративные, под балансировку.

---

## 1. Проблема

- Пространство практически ограничено: по высоте всего 20 тайлов; по ширине бесконечно,
  но управляемость и дальность ограничивают по факту.
- Стоимость зданий растёт экспоненциально (`costMul` за каждое купленное), а **выход на
  одно здание — плоский**.
- → Линейный прирост производства упирается в экспоненциальную стоимость и предел по месту.
  Это классическая «стена» idle-игры без мультипликаторов: ставить ещё зданий всё дороже,
  а отдача не растёт.

**Главный вывод раздела:** проблему нельзя решить «дешевле здания / больше места». Нужны
источники роста, **не привязанные к числу тайлов**.

---

## 2. Принцип масштабирования (ключевой вывод)

- Рост должен идти от **мультипликаторов**, независимых от количества зданий/тайлов.
- Вводим единую **«алгебру бонусов»**:
  - **внутри одной категории бонусы складываются;**
  - **между категориями — перемножаются.**
- Итоговый множитель = ∏ по категориям `(1 + bonus_категории)`. Много полу-независимых
  рычагов → игрок постоянно решает «куда вложиться», это и есть вовлечение.
- Категории-рычаги: маяки/модули · манипуляторы · конвееры · престиж-ракеты ·
  боевой престиж (ОП) · хранилище/офлайн.

Это прямо отвечает на запрос: манипуляторы между собой — аддитивно, манипуляторы ×
конвееры — мультипликативно. Мы лишь обобщаем правило на все категории.

---

## 3. Манипуляторы и конвееры как глобальные множители

Идея пользователя, оформленная в механику:

- Манипуляторы/конвееры **производятся** как предметы (ассемблеры крафтят непрерывно) и
  «вкладываются» в **ранг**, а не ставятся на карту → не занимают место → разрывают связь
  «рост ↔ площадь».
- **Манипуляторы → множитель скорости крафта** (ассемблеры, печи).
- **Конвееры → множитель пропускной способности / глобального выхода** (добыча + общий
  выпуск). Тематически логично: «руки» крафтят, «логистика» возит.
- Внутри каждого семейства — аддитивно; **семейства перемножаются**:

```
CraftMult = 1 + Σ (вклад_манипулятора × ранг)
FlowMult  = 1 + Σ (вклад_конвеера  × ранг)
LogisticsMult = CraftMult × FlowMult          // ← то самое перемножение
```

- Тиры из оригинала (растущий вклад и цена ранга):

| Манипуляторы | вклад/ранг | | Конвееры | вклад/ранг |
|---|---|---|---|---|
| Burner inserter | +2% | | Transport belt (yellow) | +3% |
| Inserter | +4% | | Fast belt (red) | +6% |
| Long-handed | +5% | | Express belt (blue) | +10% |
| Fast inserter | +7% | | Turbo belt | +15% |
| Stack inserter | +12% | | | |
| Bulk inserter | +18% | | | |

- **Диминишинг через цену ранга:** вклад ранга плоский, но цена следующего ранга растёт
  (как у престиж-валюты). Итог ограничен текущей скоростью производства, а не уходит в
  бесконечность мгновенно.
- **Решено — ручной крафт:** есть **окно ручного крафта** (§13), где игрок крафтит
  манипуляторы, конвееры и электростолбы поштучно. Каждый крафт = +1 ранг соответствующего
  семейства; **цена следующего крафта растёт** (это и есть диминишинг). Никакого линейного
  счёта миллионов предметов — управляемо и читаемо.

## 4. У зданий нет уровней (решено)

Рассматривали «апгрейд на месте» (Drill mk1→mk2→mk3, ассемблер 1→2→3) как способ выжать
«больше с одного тайла». **Отклонено.**

- **Решение:** зданиям **не даём уровней / mk-апгрейдов**. Здание — это здание; оно не
  «прокачивается» в более мощную версию.
- **Почему:** уровни зданий — это рост, **привязанный к тайлам** (улучшаешь конкретные
  поставленные здания), а §2 прямо говорит, что рост должен идти от **множителей,
  независимых от числа зданий**. Уровни дублируют эту роль хуже: добавляют микро-менеджмент
  «прокачай каждый бур» вместо одного глобального рычага.
- **Чем заменяем «больше с одного тайла»:** глобальными множителями — манипуляторы (скорость
  крафта) и конвееры (выпуск) из §3. Они и так повышают отдачу каждого существующего здания,
  **без новых тайлов и без прокачки по одному**.
- **Разные тиры зданий из Factorio** (ассемблер 1/2/3, каменная/стальная/электрическая печь)
  остаются как **отдельные здания в палитре**, открываемые наукой, — это выбор «что поставить»,
  а **не** уровень-апгрейд уже стоящего. Базовый выход берём из `base(тип)`, и всё.

## 5. Ящики и лимит пула ресурсов

Идея пользователя: общий пул имеет ёмкость, ящики её поднимают (сток ресурсов + ворота).

- **Жёсткий кап.** Пул каждого ресурса имеет потолок; ящики его поднимают. Запас выше капа
  не растёт — излишек просто **не производится** (производитель простаивает, как при полном
  буфере). Никаких множителей, никакой конвертации переполнения — чистый лимит.
- **Конкретные числа (решено):**
  - **Стартовый кап = 100** единиц каждого типа ресурса.
  - **Колбы (science packs) — без капа:** наука не складируется как сток, а сразу идёт в
    исследования (и в метрику прогресса §8), поэтому ограничивать её бессмысленно и вредно.
    Капаются только материальные ресурсы (руда, плиты, шестерёнки, схемы и т.д.).
  - **Кап общий (uniform):** каждый поставленный ящик поднимает потолок **сразу для всех**
    материальных ресурсов на свою ёмкость (без ручного распределения «этот ящик под железо» —
    держим логистику абстрактной, §9).

    `cap_на_ресурс = 100 + Σ(ёмкость каждого поставленного ящика)`

- **Тиры ящиков (решено, ×4 за тир):**

  | Ящик | +ёмкость / шт | разблокировка |
  |---|---|---|
  | Деревянный (wooden) | +200 | старт |
  | Железный (iron) | +800 | железные плиты |
  | Стальной (steel) | +3 200 | сталь |
  | Логистический (logistic) | +12 800 | logistics-tech |

  Пример: старт 100 → +1 деревянный = 300 → +1 железный = 1 100 → +1 стальной = 4 300.
- **Ящики ставятся на карту и едят место** (§1) — это честный размен «место ↔ запас»: больше
  буфера для офлайн-прогона стоит тайлов. Тиры повышают ёмкость **на тайл**, как mk-апгрейды
  (§4), поэтому поздний ящик выгоднее по площади.
- **Цена ящика растёт** за каждый поставленный того же тира (`costMul`, как у зданий) →
  диминишинг: бесконечно задирать кап одним деревянным невыгодно, нужен переход на след. тир.
- **Почему «мягкий кап» (ёмкость = множитель офлайна) — плохо (вывод):** это не кап, а
  переименованный бонус-множитель, неотличимый от §3/§8. Он убивает сток-функцию ящиков,
  не порождает решения («расширять склад или потреблять быстрее?») и тематически пустой
  (ящик не «копит офлайн», ящик хранит предметы).
- **Почему жёсткий кап не ломает idle:** он вреден только если офлайн-прогресс = наполнение
  кучи. Но выход **непрерывно потребляется** (наука → исследования, части → ракета, оборона →
  волны §7) — производство **течёт сквозь пул**, а не копится в нём, поэтому потолок по запасу
  почти не упирается в AFK. Он кусается ровно при **переизбытке без потребителя** — честный
  сигнал «ставь ящики или больше потребителей».
- Итог: ящики — **жёсткий лимит + сток + гейт прогрессии**. Хочешь держать больший запас —
  крафти и ставь ящики.

## 6. Электростолбы — пространственная механика «зоны снабжения»

Даёт неиспользуемым столбам реальную роль и возвращает значимость месту:

- Столб создаёт **радиус снабжения**; здание вне зоны **не получает глобальный логистический
  множитель** (или работает на пониженном %).
- Тиры: малый / средний / большой / подстанция (радиус растёт; подстанция связывает зоны в
  единую сеть).
- Эффект: бесконечная карта превращается в **задачу покрытия** — «место важно» (запрос
  пользователя). Опционально столбы также дают эффективность энергии в радиусе.
- **Предостережение:** не переусложнять; разумно ввести как **поздний/опциональный слой**,
  когда базовые петли уже работают.

## 7. Кусаки, загрязнение и боевой престиж (вторая петля престижа)

- **Загрязнение** копится от производства (норма на здание/мин; снижается efficiency-модулями
  и «чистыми» апгрейдами).
- **Волны:** сила растёт с накопленным загрязнением и временем. Защита — ещё неиспользуемые
  здания Factorio: пулемётная/лазерная турель (DPS), стены и ворота (буфер HP).
- **Исход столкновения:**
  - защита ≥ волна → выстоял, банкуешь немного ОП, продолжаешь;
  - защита < волна → частичный снос (теряешь здания в атакованной зоне) или полный сброс →
    **крупная выплата ОП**.
- **Почему идеально для idle:** волны идут **по таймеру и офлайн** → авто-престиж даже в AFK.
  В экране «С возвращением»: «пока вас не было — отражено N волн, получено Y ОП».
- Это **вторая, «мета»-петля** над ракетами: срабатывает реже, даёт крупнее. Создаёт
  естественный ритм risk/reward: жать на газ (больше загрязнения → больше волны → больше ОП)
  против вкладываться в оборону.

## 8. Очки престижа (ОП): формула и что улучшают

- Каноническая метрика прогресса забега — **наука** (естественная мера развития фабрики;
  уже считается в totals).
- Формула выплаты (сублинейная, чтобы каждый сброс давал относительно меньше — стандарт idle):

```
ОП_gain = floor( k · sqrt(LifetimeScience)
                 + w_r · rockets
                 + w_p · sqrt(peakProductionRate) )
```

- `sqrt` гарантирует затухание: удваивать ОП всё дольше → темп держится.
- **Тратить ОП** (категория перемножается со всеми остальными):
  - `+% глобального производства` за каждое ОП;
  - `+% защиты` (HP стен / DPS турелей) — выживать против больших волн;
  - `+ часы / ставка офлайн-капа`;
  - **стартовый набор** после сброса (ресурсы/здания), чтобы рестарт не был с нуля;
  - **×усилитель** эффектов логистики и ящиков (мета-бонус на бонусы).
- Подаётся как дерево/список апгрейдов за ОП.

## 9. Idle-специфика (сквозные требования)

- Все новые системы **обязаны тикать офлайн** (загрязнение, волны, накопление) и
  резолвиться в welcome-back — переиспользуем существующий offline-движок (`Production.step`
  кусками по 5 c).
- **Активная игра:** оптимизация раскладки, оборона, тайминг престижа.
  **Idle:** накопление ресурсов, авто-оборона, банк ОП.
- **Абстрагируем управление:** манипуляторы/конвееры — глобальные апгрейды, без физической
  маршрутизации лент (в idle никто не роутит белты вручную).
- В каждом обновлении — следить, чтобы был хотя бы один **мультипликативный** источник,
  иначе числа упрутся.

## 10. Сводный множитель (как всё стыкуется)

```
ProductionPerBuilding
  = base(тип)                                      // §4 — без уровней/mk-апгрейдов
  × moduleBonus

GlobalMultiplier
  = (1 + Σ маяки)
  × (1 + Σ манипуляторы) × (1 + Σ конвееры)      // §3, перемножение семейств
  × 1.5^rockets                                  // существующий престиж
  × (1 + Σ апгрейды-ОП)                           // §8, боевой престиж
  × supplyCoverage(столбы, §6)                    // 0..1 за пределами зоны

// §5 ящики НЕ множитель выхода: это жёсткий лимит запаса (clamp пула,
// излишек не производится). На GlobalMultiplier не влияет.

Output = Σ_зданий ProductionPerBuilding × GlobalMultiplier
```

Каждый слой — независимый рычаг; категории перемножаются → числа продолжают расти, не
требуя бесконечного места.

## 11. Поэтапный план внедрения (по приоритету)

1. **Глобальный множитель манипуляторы×конвееры (§3) + окно ручного крафта (§13.1).**
   Прямо лечит «стену», низкий риск, не ломает раскладку, рост независим от тайлов. ← начинать отсюда.
2. **Ящики как жёсткий лимит пула + окно ручного крафта и окно обзора бонусов (§5, §13).**
3. **Загрязнение + волны + защитные здания + боевой престиж ОП (§7–8).** Большая новая
   петля; даёт авто-престиж и долгосрочную цель.
4. **Электростолбы / зоны снабжения (§6).** Пространственная глубина поверх работающих петель.
5. **Балансировка чисел** — вынести все коэффициенты в `config.js` / `data/`.

## 12. Открытые вопросы (решить до реализации)

- Кап ресурсов жёсткий или мягкий? → **РЕШЕНО: жёсткий** (стартовый 100/тип, колбы без капа, §5).
- Боевой престиж сбрасывает только себя или и ракетный слой? → вероятно отдельный мета-слой.
- Манипуляторы/конвееры: ранги-валюта или прямой счёт предметов? → **РЕШЕНО: ручной крафт
  поштучно, цена растёт за крафт (§3, §13).**
- Сила волн: чистый таймер vs привязка к загрязнению? → **рекоменд. загрязнение + время.**
- Нужен ли физический роутинг хоть где-то, или всё абстрактно? → по умолчанию абстрактно.
- Как балансить, чтобы слои не «складывались в бесконечность» слишком быстро (см. §3
  диминишинг и §8 sqrt).

## 13. UI-окна (решённые факты)

Две новые поверхности интерфейса, вытекающие из механик выше.

### 13.1. Окно ручного крафта

- Список крафтящихся **апгрейд-предметов**: манипуляторы (§3), конвееры (§3), электростолбы
  (§6) — по тирам.
- Каждый клик «скрафтить» = **+1 ранг** соответствующего семейства и применяет его вклад
  (манипуляторы аддитивно внутри семейства, семейства перемножаются — §2).
- **Цена следующего крафта растёт** (геом. прогрессия от числа уже скрафченных, как у престиж-
  валюты §3). Платится произведёнными ресурсами из пула.
- Это и есть «производство манипуляторов/конвееров», но абстрагированное: предметы не
  кладутся на карту и не едят место (§1, §9) — они конвертируются в ранги.

### 13.2. Окно обзора бонусов

- Единая сводка **всех применяемых множителей** — буквально визуализация формулы §10.
- По категориям (§2): маяки/модули · манипуляторы (CraftMult) · конвееры (FlowMult) ·
  ракеты (1.5^N) · апгрейды-ОП · покрытие столбов. Для каждой — текущий вклад и
  из чего он сложился.
- Внизу — **итоговый GlobalMultiplier** (∏ по категориям) и, отдельно, лимиты пула (§5).
- Цель: игрок видит «куда вложиться выгоднее всего» (§2 — вовлечение через выбор рычага),
  не считая в уме перемножение категорий.

## 14. Полный список бонусов

Все источники бонусов, что может получить игрок. Напоминание алгебры (§2): **внутри одной
категории — складываем, между категориями — перемножаем**. Бонусы делятся на два уровня:
**на здание** (входят в `ProductionPerBuilding`) и **глобальные** (входят в `GlobalMultiplier`).
Плюс отдельно — не-множительные ресурсы (кап, оборона, офлайн).

### A. Бонусы уровня здания (`ProductionPerBuilding`, §10)

> Уровней/mk-апгрейдов у зданий нет (§4): `base(тип)` фиксирован, разные тиры зданий —
> отдельные постройки в палитре, а не прокачка стоящих.

| # | Бонус | Эффект | Источник | Стак |
|---|---|---|---|---|
| A1 | **Модуль продуктивности** | +% выпуск рецепта | модули в слотах (§ data/modules) | аддитивно в слотах |
| A2 | **Модуль скорости** | +% скорость крафта | модули в слотах | аддитивно в слотах |
| A3 | **Модуль эффективности** | −% потребление энергии (косвенно держит выпуск при дефиците) | модули в слотах | аддитивно в слотах |
| A4 | **Эффект маяка** | speed-модули соседнего маяка при половинном эффекте | маяк в радиусе (§ GameState.beaconSpeedAt) | аддитивно от маяков в радиусе |

### B. Глобальные множители (`GlobalMultiplier`, категории перемножаются)

| # | Категория | Эффект | Источник | Стак внутри |
|---|---|---|---|---|
| B1 | **Маяки** | `1 + Σ маяки` | маяки на карте | аддитивно |
| B2 | **Манипуляторы (CraftMult)** | `1 + Σ(вклад × ранг)` — скорость крафта (ассемблеры/печи) | окно ручного крафта (§3, §13.1) | аддитивно по тирам/рангам |
| B3 | **Конвееры (FlowMult)** | `1 + Σ(вклад × ранг)` — пропускная способность / общий выпуск | окно ручного крафта (§3, §13.1) | аддитивно по тирам/рангам |
| B4 | **Престиж-ракеты** | `1.5^rockets` — постоянный бонус за запуск | запуск ракеты (существующий престиж) | мультипликативно за ракету |
| B5 | **Апгрейды ОП: производство** | `1 + Σ` за вложенные очки | дерево ОП (§8) | аддитивно по очкам |
| B6 | **Покрытие столбов** | `0..1` множитель: здание вне зоны теряет глоб. логистику | электростолбы (§6) | доля покрытых зданий |

> `LogisticsMult = CraftMult × FlowMult` (B2 × B3) — главное перемножение семейств (§3).
> `GlobalMultiplier = B1 × (B2 × B3) × B4 × B5 × B6`.

### C. Дерево очков престижа (ОП, §8) — на что тратятся

| # | Апгрейд за ОП | Эффект |
|---|---|---|
| C1 | **+% глобального производства** | прямой множитель (= B5) |
| C2 | **+% защиты** | HP стен / DPS турелей — выживать против больших волн (§7) |
| C3 | **+ часы / ставка офлайн-капа** | дольше и эффективнее копится в AFK |
| C4 | **Стартовый набор** | ресурсы/здания после сброса — рестарт не с нуля |
| C5 | **×Усилитель логистики и ящиков** | мета-бонус: множит эффект B2/B3 и ёмкость ящиков (§5) |

### D. Не-множительные ресурсы (лимиты и буферы, не входят в GlobalMultiplier)

| # | Ресурс | Эффект | Источник |
|---|---|---|---|
| D1 | **Кап пула** | +ёмкость хранения на ресурс (старт 100; колбы без капа) | ящики по тирам (§5): +200/+800/+3200/+12800 |
| D2 | **Офлайн-ставка / кап** | сколько копится в AFK | база (config) + ОП C3 |

### E. Источники, открывающие/усиливающие бонусы (не сами множители)

| # | Источник | Что даёт |
|---|---|---|
| E1 | **Технологии (tech-tree)** | разблокируют здания/модули/тиры ящиков и точечные эффекты (§ data/tech) |

**Итоговая сборка (§10):**
```
ProductionPerBuilding = base(тип) × (1 + A1+A2) × A4(маяк)   // без уровней зданий, §4
GlobalMultiplier       = B1 × (B2 × B3) × B4 × B5 × B6
Output                 = Σ_зданий ProductionPerBuilding × GlobalMultiplier   // clamp по D1
```

## 15. ГИПОТЕЗА: какой бонус даёт каждый предмет

> ⚠️ **Гипотеза, числа черновые.** Цель — заземлить §3/§5/§6 в конкретные предметы и значения,
> чтобы потом проверить, как это ложится в общую концепцию. Все вклады и цены — под балансировку.

**Как читать:** «вклад/ранг» — сколько добавляет один скрафченный предмет этого типа; ранги
одного типа суммируются, типы внутри семейства суммируются, **семейства перемножаются** (§2–§3).
Цена крафта растёт за каждый купленный ранг того же типа (`costMul`) — это диминишинг (§3).

### 15.1. Манипуляторы → CraftMult (скорость крафта: ассемблеры, печи)

`CraftMult = 1 + Σ_типов (вклад_типа × ранг_типа)` — аддитивно внутри семейства.

| Предмет | вклад/ранг | базовая цена крафта | рост цены/ранг | разблок |

### 15.2. Конвееры → FlowMult (пропускная способность / общий выпуск)

`FlowMult = 1 + Σ_типов (вклад_типа × ранг_типа)` — аддитивно внутри семейства.

*Тематика:* «логистика» возит → поднимает общий выпуск/добычу. `LogisticsMult = CraftMult ×
FlowMult` — держать оба семейства ровно выгоднее, чем качать одно (перемножение, §3).

## 16. Реализуемость «скорости» и «выпуска» на движке (важно)

Вопрос: можно ли реально сделать CraftMult (скорость) и FlowMult (выпуск) — и не одно ли это
и то же? Разбор по фактическому коду `Production.step()`.

### 16.1. Что движок делает сейчас

```js
speedMul = def.speed * (M.speed + me.speed + beacon)   // число крафтов
crafts   = speedMul / rec.time * dt * rateMods          // ← клампится доступным входом
made     = rec.out * crafts * (M.yield + me.yld)        // выход за крафт
inputs   = rec.inputs * crafts                          // ← вход НЕ зависит от yield
```

В движке **уже есть два разных множительных канала** (`GameState.multipliers()` → `M.speed`,
`M.yield`), и они **не эквивалентны по побочкам**:

| | `M.speed` (скорость) | `M.yield` (выпуск/продуктивность) |
|---|---|---|
| Масштабирует | число крафтов/сек | выход за крафт |
| Потребление входа | растёт пропорционально | **не растёт** (бесплатный выход) |
| При нехватке входа | упирается в кламп — бесполезна | всё равно даёт больше |
| Добытчики (без входа) | ×выход | ×выход |
| Прогресс-бар | ускоряет | не трогает |
| Энергия | не меняет (плоское на здание) | не меняет |

### 16.2. Ответ «не одно ли это и то же?»

- Для **итогового выхода одного сытого здания** — да: `Output ∝ speed × yield`, два бонуса ×2
  взаимозаменяемы. Различие — в **побочках**: скорость жрёт вход и глохнет при голоде; выпуск
  бесплатен и снимает голод.
- **Бонус-находка:** мечта §3 «семейства перемножаются» (`CraftMult × FlowMult`) — это **ровно
  то, как `speed` и `yield` уже перемножаются в коде** (один в `crafts`, другой в `made`).
  Перемножение получается даром, если развести семейства по этим двум каналам.
- **Загвоздка:** лент в симуляции нет («один пул, no belts»), поэтому «конвеер = throughput»
  нативного механического смысла не имеет. Throughput здесь нечему ограничивать.

### 16.3. Три честных варианта (выбрать)

- **(A) Слить в один множитель.** Манипуляторы + конвееры оба льют в общий global production
  mult. Проще всего; но теряем «перемножение семейств» — это снова один аддитивный пул.
- **(B) Развести по двум каналам движка (рекомендуется как старт).**
  - **Манипуляторы → `M.speed`** (быстрее крафт; жрёт вход; ускоряет добычу). Тематика идеальна:
    «руки» двигают предметы в/из машин → скорость машины.
  - **Конвееры → `M.yield`** (бесплатный доп-выход на тот же вход; снимает голод входа).
    Перемножение с манипуляторами выходит само (§16.2). **Минус — тематика:** конвееры как
    «продуктивность» — натяжка; подаём как «логистика довозит без потерь → больше готового».
  - Почти нулевая работа: добавить вклады в `multipliers()`, остальное движок уже считает.
- **(C) Ввести абстрактный throughput-кап.** Конвееры поднимают «логистическую ёмкость»,
  скорость её потребляет; не хватает ёмкости — выпуск режется. Честный «throughput» и лучшая
  тематика, но это **новая система** (больше движковой работы). Кандидат на «сделать правильно
  позже», поверх (B).

**Вывод:** реализуемо — да, тривиально для (A)/(B). «Одно и то же» — только если льём в один
канал; разные каналы (B) дают реально разное поведение (вход-затратная скорость vs бесплатный
выпуск) и бесплатное перемножение. Тематическую натяжку конвееров в (B) чиним позже через (C).
