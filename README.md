# Factorio Idle

A browser idle/incremental game inspired by Factorio — build a production chain,
research a tech tree, manage power, insert modules, and launch a rocket to prestige.
Vanilla JavaScript (ES modules), no framework, no build step.

## Running

Because the game uses native ES modules (`import`/`export`), it must be served over
HTTP — opening `index.html` directly from `file://` will be blocked by the browser.

From the project folder:

```bash
# any static server works; pick one
python3 -m http.server 8080      # then open http://localhost:8080
# or
npx serve .
```

(`npm start` runs the python one-liner above.)

State is saved to `localStorage` every 10 seconds and on tab close. On load you can
**Continue** (with offline progress credited, up to 8 h at 50%) or start a **New Game**.

```
    ├── mapview.js          # MapView — canvas renderer + mouse placement/pan/remove of building entities
    ├── gameState.js        # GameState — state, entities on the map, multipliers, beacon radius, unlock checks
    ├── production.js       # Production — per-tick sim over placed entities: power, crafting, input limiting
    ├── research.js         # Research — start / advance / complete technologies
    ├── save.js             # Save — localStorage persistence (map seed + entities), offline progress
    ├── ui.js               # UI — resources, building palette, entity inspector, research, prestige
    └── data/               # pure data tables (no logic) — edit these to tune the game
        ├── resources.js    # every item + display + tier
        ├── recipes.js      # inputs / output / craft time per recipe
        ├── buildings.js    # producers: speed, energy, cost, module slots, unlock
        ├── power.js        # generators: MW, fuel
        ├── modules.js      # speed / productivity / efficiency modifiers
        └── tech.js         # technology tree: cost, prerequisites, effects
```

## Architecture

The five modules from the spec map 1:1 to files: **GameState · Production · Research ·
UI · Save**. Game logic is fully separated from the data tables in `js/data/`, so
balancing or adding content rarely touches the engine.

- **Map & entities:** the world is infinite in width and 20 tiles tall, generated by
  `MapGen` from a per-game seed (stored in the save). Buildings are individual **entities**
  `{type,x,y,recipe,modules}` placed on the map (2×2 footprint) via the palette in `UI`;
  `MapView` draws the canvas and handles placement/pan/remove. Drills must cover a matching
  ore patch; everything else goes on land. Resources live in one shared pool (no belts).
- **Tick:** `setInterval` every 200 ms (5 ticks/sec). Each tick `Production.step()` iterates
  the placed entities, then `UI.renderDynamic()` refreshes the screen + redraws the map.
- **Production pass** is ordered by recipe tier so inputs are produced before their
  consumers within the same tick, and each recipe is clamped to available inputs.
- **Beacons** are radius buildings: their speed modules boost (at half effect) any building
  within Chebyshev `radius` tiles — see `GameState.beaconSpeedAt()`.
- **Power** is computed first each tick (summed over placed generators); a deficit scales all
  consumers' speed by the production/consumption ratio. No grid exists until the
  `electricEnergy` tech, so the energy widget stays hidden in the burner era.
- **Offline progress** reuses the exact same `Production.step()` in coarse 5 s chunks.

## Data generation

`js/data/resources.js`, `recipes.js` and `buildings.js` are **auto-generated** from
the bundled Factorio base game data (`Factorio/data/base/prototypes/*.lua`) by
`tools/extract.py`. It computes the transitive crafting chain of the six science
packs plus the rocket-part prestige goal (47 items / 41 recipes), derives tiers from
dependency depth, and pulls real names, colours (recipe tints) and amounts. The
single-output engine simplifies Factorio's multi-output oil recipes to one crude-oil
derivative per fluid. Re-run after tweaking the config block at the top of the script:

```bash
python3 tools/extract.py
```

`tech.js` is hand-authored (real Factorio tech names + science-pack costs) because its
effects are curated for this engine — edit it directly.

## Extending

- **Add a resource / recipe / building / tech:** edit `tools/extract.py` (data tables) and
  re-run it, or edit the matching file in `js/data/` directly for one-offs.
  New `tier` values automatically slot into the production ordering.
- **New tech effects:** add a key under `effect` in `data/tech.js` and handle it in
  `Research.complete()` (for one-shots) or `GameState.multipliers()` (for ongoing bonuses).
- **Balance:** tweak `js/config.js` (tick rate, offline rate/cap, rocket goal) and the
  `costMul` / `speed` / `time` fields in the data tables.

## Performance — rendering (planned optimization)

> Idea captured for later — **not yet implemented.**

`MapView.render()` currently does a **full scene redraw every call**, and is called far
more often than needed:

- 5×/sec from the game tick (`UI.renderDynamic()` → `MapView.render()`),
- **once per canvas `mousemove`, untrottled** (60–150 full redraws/sec while the cursor moves),
- once per pan-drag frame and wheel event,
- ~60/sec during hand-mining (the pickaxe RAF loop).

Each redraw, for the ~460 visible tiles (≈23×20 at a 900px-wide canvas):

- recomputes deterministic procedural noise (`waterAt / beachAt / desertAt / drygrassAt /
  highlandAt / oreAt / terrainType`) for every tile, every frame, even though the map is
  immutable for a given seed;
- the transition/fade pass calls `terrainType` ~9× per tile (self + 8 neighbours), so each
  tile's biome is evaluated ~9 times per pass;
- issues ~500–700 `drawImage` calls (terrain + fades + ore + obstacles + entities).

It's cheap at the 5/sec tick cadence, but wasteful during mouse interaction: hover changes
one tile yet triggers a complete static+dynamic redraw.

**Planned fixes, by impact:**

1. **Cache the static layer.** Render terrain + transitions + ore + obstacles once into an
   offscreen canvas keyed by `(seed, camPx, canvas size)`; on `render()` blit that single
   image, then draw only the dynamic layer (entities, placement ghost, selection outline,
   progress bars, mining pickaxe). Invalidate only on pan / resize / obstacle-clear /
   map-change. Removes ~95% of per-frame work when the camera is static (the common case).
2. **Throttle via `requestAnimationFrame`.** Replace direct `render()` calls with a
   `requestRender()` that sets a dirty flag and schedules a single rAF, coalescing a burst of
   `mousemove` events into ≤1 render per display frame.
3. **Memoize map queries.** Cache `terrainType / oreAt / waterAt` results in a `Map` keyed by
   `"x,y"` (the map never changes mid-game) — kills the ~9× redundancy in the fade pass and all
   cross-frame recomputation. Largely subsumed by #1 if the static layer is cached.
4. **Late-game:** add a spatial index for `entityAt` instead of a linear `Array.find` on every
   `mousemove`.

Separately, `UI.renderDynamic()` also runs every tick and walks all `RESOURCES` and
`BUILDINGS + POWER` (resource list + palette gating) — a DOM cost independent of the canvas,
worth revisiting if tick work becomes a bottleneck.

## Status

Implements the full MVP chain (iterations 1–2) plus a working tech tree, modules,
energy, offline progress, statistics, and rocket prestige. The tech tree ships with a
